AWS AI Certification Study Coach Agent
An AI-powered AWS certification study assistant built with Python, the Strands Agents SDK, Amazon Bedrock (Amazon Nova Micro), and Amazon Bedrock AgentCore.

The project combines certification preparation with hands-on AWS labs. Students can answer multiple-choice questions, review official AWS study materials, and have selected lab configurations checked against real AWS resources.
Deployment status: An initial AgentCore Runtime prototype is deployed in eu-central-1. The expanded question bank and hands-on lab tools have been validated locally, including real AWS API integrations, but have not yet been deployed to AgentCore Runtime.

Features
Certification question bank
- 50 curated multiple-choice questions across Amazon S3, IAM, Lambda, EC2, and VPC (10 per topic).
- Random question selection with topic and difficulty filtering.
- Answer checking with explanations.
- Questions stored in [`app/agent/data/questions.json`](app/agent/data/questions.json).
- Current questions are predefined, not dynamically generated by a model.
Agent tools: generate_practice_question, check_practice_answer.
Study materials search
- Keyword search across curated official AWS documentation for S3, IAM, and Lambda.
- Case-insensitive matching; empty and unknown queries are handled.
Agent tool: search_study_materials.
Hands-on AWS labs
Lab resources are created manually by the student. The verification tools use read-only AWS APIs to check the resulting configurations.
Lab	Verification criteria	Real AWS validation
S3 Secure Bucket	Versioning, all four Block Public Access settings, SSE-S3 default encryption; also checks ownership and region	3/3 passed
Lambda Configuration	Python 3.12 runtime, 128 MB memory, 10-second timeout, Active state, execution role in expected account	5/5 passed
IAM Least Privilege	Expected trust policy, one specific inline policy, no attached policies, s3:GetObject and scoped bucket ARN	5/5 passed


Agent tools: generate_lab_task, verify_lab_task (S3); generate_lambda_lab_task, verify_lambda_lab_task; generate_iam_lab_task, verify_iam_lab_task.

The checks are tailored to these exercises. They do not constitute a complete AWS security or compliance audit. In particular, IAM policy checks do not establish the full effective permissions of a role.

Development and testing
Run the unit tests from the repository root in Windows PowerShell:
& .\app\agent\.venv\Scripts\python.exe -m unittest discover -s test -p "test_*.py" -v
Latest reported result: 39 tests passed.

Unit tests cover the question bank, study-materials search, and S3, Lambda, and IAM lab verifiers. Cloud calls are mocked in automated verifier tests; real AWS integration tests were run separately.
AWS integration validation
The three labs were also tested against real AWS resources in eu-central-1:
- S3: Bucket ownership and region were checked; Versioning, Block Public Access, and default SSE-S3 encryption passed (3/3).
- Lambda: Runtime, memory, timeout, state, and execution-role account checks passed (5/5).
- IAM: Lab-role trust policy, inline and attached policy checks, allowed action, and resource scope passed (5/5).
- End-to-end: Strands Agent successfully invoked each verification tool with Amazon Bedrock Nova Micro and explained the results.
The S3, Lambda, and IAM read-only API checks were exercised through an AWS IAM Identity Center read-only profile. Local end-to-end agent invocations used a separate SSO profile with Bedrock inference access. These developer credentials are not the intended production runtime identity.
Local AWS configuration
The lab verification tools require:
- AWS_STUDY_ACCOUNT_ID: the expected 12-digit AWS account ID.
- AWS credentials with only the read permissions required for the relevant lab.
- AWS Region eu-central-1 for the current S3 and Lambda exercises.
Example of setting local environment variables in PowerShell:
$env:AWS_PROFILE = "study-coach-readonly"
$env:AWS_STUDY_ACCOUNT_ID = "<your-12-digit-account-id>"
$env:AWS_REGION = "eu-central-1"
$env:AWS_DEFAULT_REGION = "eu-central-1"
Do not store AWS credentials in the repository. The read-only SSO profile used for lab verification does not necessarily have Bedrock inference permissions.
Security and deployment status
Runtime permissions
- AgentCore Runtime uses a dedicated IAM execution role.
- A customer-managed permissions boundary, AWSStudyCoachRuntimeBoundary, is attached to the deployed role.
- A direct cloud invocation was verified after application of the boundary, including add_numbers(7, 5) = 12.
- A boundary-only CloudFormation change set was executed successfully and the stack reached UPDATE_COMPLETE.
- A permissions boundary limits maximum permissions; it does not grant permissions by itself.
CloudFormation deployment permissions
- A separate role, StudyCoachCloudFormationExecutionRole, was created and initially tested with scoped permissions.
- That role is not assigned to the existing CloudFormation stack.
- The deployment-policy template in [`security/`](security/) remains a draft and is not production-ready.
- The CDK diff has previously shown an unrelated CodeZip artifact change. Do not run an unrestricted cdk deploy until that difference and the deployment permissions have been reviewed.
Lab safeguards and limitations
- Verifiers read configurations; they do not create, update, invoke, or delete student resources.
- S3 and Lambda labs expect resource names beginning with study-coach-lab-.
- The IAM lab checks the designated study-coach-lab-s3-reader role and its expected policy shape.
- The verification tools validate account identity and relevant regional constraints, but naming checks alone are not an IAM security boundary.
- A dedicated least-privilege runtime identity is needed before cloud deployment of the new lab tools.
- Lab-created AWS resources should be cleaned up after testing to avoid unnecessary costs.
