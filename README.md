# AWS AI Certification Study Coach Agent

An AI-powered AWS certification study assistant built with Python, the Strands Agents SDK, Amazon Bedrock, and Amazon Bedrock AgentCore.

The project combines AWS certification preparation, interactive practice exams, progress tracking, and hands-on AWS labs. Students can answer multiple-choice questions, search curated official AWS documentation, and verify selected lab configurations against real AWS resources.

> **Deployment status:** An initial AgentCore Runtime prototype is deployed in `eu-central-1` and was verified with Amazon Nova Micro and the `add_numbers` tool. The expanded study tools, AWS labs, Exam Mode, Student Progress, and the new Claude model configuration have been tested **locally** but have **not yet been deployed to AgentCore**.

## Features

### Certification Question Bank

- 50 curated multiple-choice questions across Amazon S3, IAM, Lambda, EC2, and VPC (10 per topic).
- Random question selection with topic and difficulty filtering.
- Answer validation with explanations.
- Questions are predefined, not dynamically generated by the model.
- Source: [`app/agent/data/questions.json`](app/agent/data/questions.json).

Agent tools: `generate_practice_question`, `check_practice_answer`.

### Study Materials Search

- Searches curated official AWS documentation for S3, IAM, and Lambda.
- Supports case-insensitive search and handles empty or unknown queries.

Agent tool: `search_study_materials`.

### Hands-on AWS Labs

Students create lab resources themselves. The verification tools inspect their configurations using read-only AWS API calls through `boto3`.

| Lab | What is verified | Real AWS validation |
| --- | --- | --- |
| S3 Secure Bucket | Versioning, all four Block Public Access settings, default SSE-S3 encryption, ownership and region | 3/3 passed |
| Lambda Configuration | Python 3.12 runtime, 128 MB memory, 10-second timeout, Active state, execution role in the expected account | 5/5 passed |
| IAM Least Privilege | Expected trust policy, designated inline policy, no attached managed policies, `s3:GetObject`, and a scoped bucket ARN | 5/5 passed |

Agent tools:

- S3: `generate_lab_task`, `verify_lab_task`
- Lambda: `generate_lambda_lab_task`, `verify_lambda_lab_task`
- IAM: `generate_iam_lab_task`, `verify_iam_lab_task`

These checks validate specific exercises, not complete AWS security or compliance. In particular, IAM policy checks do not establish a role's full effective permissions.

### Practice Exam Mode

- Start an exam with 1 to 20 random questions, subject to the number available for the selected topic.
- Choose a specific AWS topic or a mix of topics.
- Answer one question at a time without revealing correct answers during the exam.
- Receive a score, percentage, correct answers, and explanations after finishing.
- Use a **project-defined 70% practice passing threshold**, not an official AWS Certification passing score.

Agent tools: `start_practice_exam`, `submit_exam_answer`, `finish_practice_exam`.

Implementation: [`app/agent/exam_mode.py`](app/agent/exam_mode.py).

Exam sessions currently live in Python process memory and disappear after a process restart. This approach is not suitable for a multi-instance cloud deployment.

### Student Progress Tracking

Completed exams are saved to a local JSON file and can be reviewed after restarting Python:

- Number of completed and passed exams.
- Total questions and overall answer accuracy.
- Accuracy by AWS topic.
- Five most recent completed exams.
- Duplicate prevention for the same exam session.

Agent tool: `get_student_progress`.

Implementation: [`app/agent/progress.py`](app/agent/progress.py).

Local storage: `app/agent/data/student_progress.json` (excluded from Git through `.gitignore`). This is a **single-user local development store**, not a production database. Cloud deployment requires durable storage, authenticated user identity, data isolation, and concurrency-safe session handling.

## AI Model Configuration

The default model for **local development** is now **Anthropic Claude Haiku 4.5**, accessed through Amazon Bedrock. Previously, the agent used Amazon Nova Micro.

- Default Bedrock model ID: `eu.anthropic.claude-haiku-4-5-20251001-v1:0`
- AWS Region for requests: `eu-central-1`
- Inference mode: EU cross-region inference profile (processing can take place in supported EU AWS Regions).
- Configuration file: [`app/agent/model/load.py`](app/agent/model/load.py)
- The model can be overridden using the `BEDROCK_MODEL_ID` environment variable.

Local PowerShell example for Claude:

```powershell
$env:AWS_PROFILE = "study-coach-sso"
$env:AWS_REGION = "eu-central-1"
$env:AWS_DEFAULT_REGION = "eu-central-1"
$env:BEDROCK_MODEL_ID = "eu.anthropic.claude-haiku-4-5-20251001-v1:0"
```

To switch back to Nova Micro for local comparison:

```powershell
$env:BEDROCK_MODEL_ID = "eu.amazon.nova-micro-v1:0"
```

The Claude Haiku 4.5 EU inference profile was confirmed `ACTIVE`, a direct Bedrock Converse call returned `Claude connection OK`, and a local Strands Agent invocation returned `7 plus 5 equals 12.` using the `add_numbers` tool. **Claude has not yet been validated with every lab and exam workflow or deployed to AgentCore.**

## Development and Testing

From the repository root in Windows PowerShell:

```powershell
uv sync --locked --project app/agent --python 3.12
& .\app\agent\.venv\Scripts\python.exe -m unittest discover -s test -p "test_*.py" -v
```

GitHub Actions runs the unit suite and TypeScript CDK compilation on pushes and pull requests. These checks do not deploy resources or call Bedrock. Exam tests use temporary progress files, keeping local student history separate from test results.

For a local agent server after configuring AWS credentials:

```powershell
Set-Location app/agent
& .\.venv\Scripts\python.exe main.py
```

Use the runtime payload described in [`app/agent/README.md`](app/agent/README.md). Running model prompts requires Bedrock access and incurs inference charges.

**Latest confirmed result: 53 tests passed (`OK`).** Tests cover Exam Mode, Student Progress, the question bank, study-materials search, and S3/Lambda/IAM lab verification. Unit tests include mocks for AWS API behavior; real AWS integration tests were performed separately.

Real AWS integration validation:

- **S3:** Ownership and region checks; Versioning, Block Public Access, and default SSE-S3 encryption passed (3/3).
- **Lambda:** Runtime, memory, timeout, state, and execution-role account checks passed (5/5).
- **IAM:** Prescribed trust and policy configuration checks passed (5/5).
- **Agent integration:** Strands Agent with Nova Micro invoked the lab tools and started a practice exam during earlier local integration tests.
- **Manual exam:** A two-question practice exam finished with correct grading and explanations.
- **Progress persistence:** Completed exam records were visible from a subsequent Python process.
- **Claude integration:** Bedrock Converse and Strands `add_numbers(7, 5)` calls succeeded; all 53 Python unit tests also passed after changing the local default model.
- **Console output:** Disabling the default Strands console callback (`callback_handler=None`) produced one clean response in a local smoke test. Further streamed-output validation is pending.

The manual test driver `test_exam_manual.py` is for local development and is not required in the repository.

## Local AWS Configuration

For AWS lab verification, use a profile with the required read-only API permissions and set the expected account ID:

```powershell
$env:AWS_PROFILE = "study-coach-readonly"
$env:AWS_STUDY_ACCOUNT_ID = "<your-12-digit-account-id>"
$env:AWS_REGION = "eu-central-1"
$env:AWS_DEFAULT_REGION = "eu-central-1"
```

The `study-coach-readonly` profile may not have Bedrock streaming inference permissions. Earlier local agent integration tests used a separate SSO profile with Bedrock access. Developer SSO credentials must not be hardcoded, committed, or used as the production runtime identity.

## Security and Deployment Status

### Runtime Permissions

- AgentCore Runtime uses a dedicated IAM execution role.
- The customer-managed permissions boundary `AWSStudyCoachRuntimeBoundary` is attached to the deployed role.
- Direct cloud invocation succeeded after the boundary was applied: `add_numbers(7, 5) = 12`.
- A boundary-only CloudFormation change set was executed successfully, with the stack reaching `UPDATE_COMPLETE`.
- A permissions boundary limits maximum permissions; it does not grant access on its own.
- Runtime permissions for the Claude inference profile and new study/lab tools require review before deployment.

### CloudFormation Deployment Permissions

- The separate `StudyCoachCloudFormationExecutionRole` was created and initially tested with scoped permissions.
- This role has **not** been assigned to the existing CloudFormation stack.
- The deployment-policy template in [`security/`](security/) is still a draft, not production-ready.
- A previous CDK diff included an unrelated CodeZip artifact change. **Do not run an unrestricted `cdk deploy`** until that difference and deployment permissions have been reviewed.

### Lab Safeguards

- Verification tools read AWS resource configurations; they do not create, modify, or delete student resources.
- S3 and Lambda exercises expect resource names beginning with `study-coach-lab-`.
- IAM checks target the prescribed `study-coach-lab-s3-reader` role and policy shape.
- Naming conventions alone are not IAM security boundaries.
- A dedicated least-privilege runtime identity is needed before deploying lab tools to AgentCore.
- Clean up temporary student-created AWS resources after testing to avoid unnecessary cost.
