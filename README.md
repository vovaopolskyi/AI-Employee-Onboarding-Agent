# AWS AI Certification Study Coach Agent

An AI-powered AWS certification study assistant built with Python, the Strands Agents SDK, Amazon Bedrock (Amazon Nova Micro), and Amazon Bedrock AgentCore.

The project combines certification preparation, interactive practice exams, progress tracking, and hands-on AWS labs. Students answer multiple-choice questions, review curated official AWS documentation, and verify selected lab configurations against real AWS resources.

> **Deployment status:** An initial Amazon Bedrock AgentCore Runtime prototype is deployed in `eu-central-1`, with the `add_numbers` tool verified in the cloud. The certification tools, Exam Mode, Student Progress, and AWS lab verification tools have been implemented and tested locally but have **not** yet been deployed to AgentCore Runtime.

## Features

### Certification Question Bank

- 50 curated multiple-choice questions across Amazon S3, IAM, Lambda, EC2, and VPC (10 questions per topic).
- Random question selection with topic and difficulty filtering.
- Answer validation with explanations.
- Questions are predefined, not dynamically generated by a model.
- Source: [`app/agent/data/questions.json`](app/agent/data/questions.json).

Agent tools: `generate_practice_question`, `check_practice_answer`.

### Study Materials Search

- Searches curated official AWS documentation for S3, IAM, and Lambda.
- Supports case-insensitive searches and handles empty or unknown queries.

Agent tool: `search_study_materials`.

### Hands-on AWS Labs

Students create lab resources themselves. Verification tools use read-only AWS API calls through `boto3` to inspect their configurations.

| Lab | What is verified | Real AWS validation |
| --- | --- | --- |
| S3 Secure Bucket | Versioning, all four Block Public Access settings, default SSE-S3 encryption, ownership and region | 3/3 passed |
| Lambda Configuration | Python 3.12 runtime, 128 MB memory, 10-second timeout, Active state, execution role in the expected account | 5/5 passed |
| IAM Least Privilege | Expected trust policy, designated inline policy, no attached managed policies, `s3:GetObject` and scoped bucket ARN | 5/5 passed |

Agent tools:

- S3: `generate_lab_task`, `verify_lab_task`
- Lambda: `generate_lambda_lab_task`, `verify_lambda_lab_task`
- IAM: `generate_iam_lab_task`, `verify_iam_lab_task`

These checks validate the specified exercises; they are not a comprehensive AWS security or compliance audit. In particular, IAM policy checks do not prove a role's complete effective permissions.

### Practice Exam Mode

Interactive practice exams use the existing 50-question bank:

- Start an exam with 1 to 20 randomly selected questions, subject to available questions for the selected topic.
- Select one AWS topic or a mixture of topics.
- Answer questions one at a time without seeing correct answers during the exam.
- Receive a final score, percentage, correct answers, and explanations.
- Use a **project-defined 70% practice passing threshold**. This is not an official AWS Certification passing score.

Agent tools: `start_practice_exam`, `submit_exam_answer`, `finish_practice_exam`.

Implementation: [`app/agent/exam_mode.py`](app/agent/exam_mode.py).

Exam sessions currently live in Python process memory and disappear after a restart. They are not yet suitable for multi-instance cloud deployment.

### Student Progress Tracking

Completed exams are saved to a local JSON file and can be reviewed after restarting Python:

- Number of completed and passed exams.
- Total questions and overall answer accuracy.
- Accuracy by AWS topic.
- Five most recent completed exams.
- Duplicate prevention for the same exam session.

Agent tool: `get_student_progress`.

Implementation: [`app/agent/progress.py`](app/agent/progress.py).

Local storage: `app/agent/data/student_progress.json` (excluded from Git by `.gitignore`). This is a **single-user local development store**, not a production-grade database. Cloud deployment will require durable storage, user identity, access isolation, and concurrency-safe session handling.

## Local AWS Configuration

The lab verification tools require an expected AWS account ID and AWS credentials with appropriate read permissions. For the current labs, use `eu-central-1`.

```powershell
$env:AWS_PROFILE = "study-coach-readonly"
$env:AWS_STUDY_ACCOUNT_ID = "<your-12-digit-account-id>"
$env:AWS_REGION = "eu-central-1"
$env:AWS_DEFAULT_REGION = "eu-central-1"
```

Do not commit credentials. The read-only SSO profile used for lab checks may not have the Bedrock streaming inference permissions required to invoke Nova Micro. Local agent integration checks used a separate SSO profile with Bedrock access; this is **not** the intended production runtime identity.

## Security and Deployment Status

### Runtime Permissions

- AgentCore Runtime uses a dedicated IAM execution role.
- The customer-managed permissions boundary `AWSStudyCoachRuntimeBoundary` is attached to that role.
- A direct cloud invocation succeeded after applying the boundary: `add_numbers(7, 5) = 12`.
- A boundary-only CloudFormation change set was executed successfully and the stack reached `UPDATE_COMPLETE`.
- A permissions boundary defines a maximum permission limit; it does not grant permissions by itself.

### CloudFormation Deployment Permissions

- The separate `StudyCoachCloudFormationExecutionRole` was created and initially tested with scoped permissions.
- This role has **not** been assigned to the existing CloudFormation stack.
- The deployment-policy template in [`security/`](security/) is still a draft, not production-ready.
- A previous CDK diff included an unrelated CodeZip artifact change. **Do not run an unrestricted `cdk deploy`** until the artifact difference and deployment permissions have been reviewed.

### Lab Safeguards

- Verification tools read AWS resource configurations; they do not create, modify, or delete student resources.
- S3 and Lambda exercises expect resource names beginning with `study-coach-lab-`.
- IAM checks target the prescribed `study-coach-lab-s3-reader` role and policy shape.
- Naming conventions alone are not IAM security boundaries.
- A dedicated least-privilege runtime identity is needed before deploying the lab tools to AgentCore.
- Clean up temporary student-created AWS resources after testing to avoid unnecessary cost.
