# AWS AI Certification Study Coach Agent

An AI-powered AWS certification study assistant built with **Python**, **Strands Agents SDK**, **Amazon Bedrock**, and **Amazon Bedrock AgentCore**.

The project combines certification questions, curated AWS documentation, and hands-on labs verified against real AWS resources.

> **Deployment status:** An initial agent is deployed to AgentCore Runtime. The expanded question bank and hands-on lab tools have been tested locally, but have **not yet been deployed** to AgentCore Runtime.

## Features

- **Certification question bank:** 50 curated multiple-choice questions covering S3, IAM, Lambda, EC2, and VPC (10 per topic).
- **Practice questions:** Random selection by topic and difficulty, with answer checking and explanations.
- **Study materials search:** Curated links to official AWS documentation for S3, IAM, and Lambda.
- **Hands-on labs:** Guided tasks with read-only verification of real AWS resources.
- **Agent integration:** Strands tools orchestrated with Amazon Bedrock Nova Micro.

## Hands-on AWS Labs

Lab resources are created manually by the student. Each verifier uses AWS API read operations and returns structured checks and a score.

| Lab | Verification | Real AWS Result |
| --- | --- | ---: |
| S3 Secure Bucket | Versioning, Block Public Access, SSE-S3 encryption | **3/3 PASS** |
| Lambda Configuration | Runtime, memory, timeout, state, execution role account | **5/5 PASS** |
| IAM Least Privilege | Trust policy, inline policy, absence of attached policies, allowed action and S3 resource scope | **5/5 PASS** |

All three lab verification tools have been invoked successfully through a local Strands Agent using Amazon Bedrock Nova Micro.

### Lab 001: S3 Secure Bucket

Create a bucket named with the prefix `study-coach-lab-` in `eu-central-1` and configure:

1. S3 Versioning enabled.
2. All four Block Public Access settings enabled.
3. Default encryption using SSE-S3 (`AES256`).

The verifier also checks the expected account owner and bucket region and distinguishes API access errors from failed configuration checks.

Tools: `generate_lab_task`, `verify_lab_task`.

### Lab 002: Lambda Configuration

Create a Lambda function with the prefix `study-coach-lab-` in `eu-central-1` and configure:

1. Runtime: `python3.12`.
2. Memory: `128 MB`.
3. Timeout: `10 seconds`.
4. Function state: `Active`.
5. Execution role belonging to the expected AWS account.

The verifier reads configuration without invoking the function. Checking the role's AWS account does **not** prove that its permissions are least-privilege.

Tools: `generate_lambda_lab_task`, `verify_lambda_lab_task`.

### Lab 003: IAM Least Privilege

Create the training role `study-coach-lab-s3-reader` with:

1. Trust policy for `lambda.amazonaws.com`.
2. One inline policy named `StudyCoachLabS3ReadPolicy`.
3. Permission `s3:GetObject` scoped to the designated training bucket's objects.
4. No additional attached managed policies or inline policies.

The verifier checks the prescribed policy structure. It is **not** a comprehensive evaluation of effective AWS permissions, which may also depend on other IAM controls.

Tools: `generate_iam_lab_task`, `verify_iam_lab_task`.

## Development and Testing

Run unit tests from the repository root in **PowerShell**:

```powershell
cd C:\dev\AWSStudyCoach
& .\app\agent\.venv\Scripts\python.exe -m unittest discover -s test -p "test_*.py" -v
```

**Latest validated local result: 39 tests passed.**

Tests cover the question bank, study materials search, and S3, Lambda, and IAM lab verification using mocked AWS clients. Integration tests were also performed manually against real resources in `eu-central-1`.

Manual end-to-end agent tests may incur Amazon Bedrock charges and require an AWS profile with model invocation permissions.

## Security

- AWS credentials are not stored in source code. Local access uses IAM Identity Center profiles with temporary credentials.
- `AWS_STUDY_ACCOUNT_ID` is required for the hands-on lab verifier configuration.
- Lab tools perform read-only API operations; students create and clean up resources separately.
- Lab names, AWS account ownership, and supported region are checked where applicable.
- Local end-to-end Bedrock tests used an existing administrative SSO profile because the read-only profile lacked `bedrock:InvokeModelWithResponseStream`. This is **not** the intended production setup.
- A dedicated least-privilege runtime identity is needed before deploying the expanded lab tools.
- IAM checks validate a specific training configuration and do not replace a complete security review.

### AgentCore Runtime Boundary

The initial deployed AgentCore Runtime uses a dedicated execution role with the `AWSStudyCoachRuntimeBoundary` permissions boundary. Cloud invocation of the `add_numbers` tool was successfully verified after the boundary was applied.

A separate `StudyCoachCloudFormationExecutionRole` has been prepared with initial scoped permissions, but the restricted CloudFormation deployment workflow is not yet complete. Review the documents and policy templates in `security/` before modifying the stack.

**Do not run an unrestricted `cdk deploy` until the unintended CodeZip artifact difference and deployment permissions have been reviewed.**
